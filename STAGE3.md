## Bugs found and fixed while finishing the slice (all real, all caught by the new spike)
1. **Attempt counter never accumulated** — `resume_travel()` reset `rec.attempts = 0` on every failed path,
   so `MAX_PATH_ATTEMPTS` could never be reached and no blacklist was ever written. Attempts are now per-target
   and survive a failed command; a fresh target resets them in `patrol.step`.
2. **Failed-path blacklist had no target** — the fail completion event names the *patroller*, not its target;
   `rec.target_un` was cleared on the first failure, so the third failure blacklisted nothing. `on_command_completed`
   now keeps `rec.target_un` across retries (`resume_travel(..., keep_target=true)`) and clears it only on
   blacklist or success.
3. **Stale lease timer could end a live patrol** — `patrol.lease` validated the registry/state but never the
   timer's generation `seq`, so a lease from a preempted generation ended a new patrol. `valid()` now also
   checks `seq == nil or seq == rec.seq`, and `patrol.step`/`patrol.engage`/`patrol.lease` all pass `d.seq`.
   This is exactly the stale-timer regression the PLAN demanded; the spike caught it and the fix is verified.

## Mandatory scheduler-handler audit — can a stale timer overwrite a live patrol?
Every `scheduler.register` handler (31 total; `grep -rn 'scheduler.register' mod/scripts/*.lua`) and its guard.
A stale timer is harmless if it either (a) cannot target a patrolling unit's `unit_state`, or (b) calls a function
that itself rejects patrol states.

**Regression case** (`m3_patrol`, phase C): while a live patrol exists, the spike schedules a stale
`construct.finish` (`WORK_TICKS`), a stale `work.finish` (1 tick), and a stale `patrol.lease` with a mismatched
`seq` (2 ticks), then asserts after 50 ticks that the patrol state and registry are unchanged. It also fires
`MAX_PATH_ATTEMPTS+2` failed-path completions and asserts the unit is never deleted
(`allow_destroy_when_commands_fail = false`, militia prototype) and the target is blacklisted. All pass.

## Determinism attribution
Previous gate checksum `713316852` → new `1550186985`. Two independent causes, both expected:
1. **Prototype-table hash**: new `colony-patrol-post` entity/item/recipe, `colony-patrol-marker` selection tool
   plus two custom inputs, and the `colony-patrol-post` technology change Factorio's prototype hash exactly as
   Stage 1/2's new prototypes did.
2. **Gameplay divergence**: new `colony.patrol_posts`/`patrols` registries, staggered `patrol.dispatch` timer and
   patrol behaviour (militia forming routes and striking nests) change the simulation even though existing
   towns' non-patrol behaviour is untouched. No existing rule was altered except adding guards that skip the
   new patrol states.

## Deviations from PLAN / reviewer scrutiny points
- **No `s20_nest` probe**: PLAN made it conditional on patrols being silently deleted on failed paths.
  s19_defence already proved `allow_destroy_when_commands_fail = false` keeps the unit alive and m3_patrol
  re-proves it with repeated synthetic failures, so no extra probe was needed.
- **Nest damage in the spike is applied through the shared `militia.patrol_strike` path directly** (as the biter
  kill already was), not by waiting for `target_select` to choose a spawner over its own continuous stream of
  near-spawns. The autonomous engagement loop is still exercised (`patrol engages a hostile`, state
  `patrol-engage` / `target_un` observed); the direct strike isolates the damage rule and keeps the test
  deterministic. A reviewer who wants an end-to-end "patrol autonomously targets a nest with no other hostiles"
  case should add a dedicated scenario where the spawner cannot emit units.
- **`patrol.step` scans with a 45-tick period over a 16-tile box** (`find_entities_filtered`, one call per live
  patrol per 45 ticks), not per tick; the dispatch timer stops entirely when no post with waypoints exists.
- **Gear is deliberately kept on whistle preemption** (`abort_intents.gear` carries it into the lease, as for
  any militia) — the route claim is released but the rifle is never returned to the Armory mid-order.
- **Bytecode**: `scripts/__pycache__/artlib.cpython-313.pyc` restored with `git checkout --` before commit;
  no compiled bytecode is committed.
- **Residual non-blocker**: patrols use the cached route when their post is mined mid-loop (active patrols finish
  the loop; the next dispatch will not re-post them) — a deliberate, deterministic choice documented in
  `scripts/patrol.lua`'s `on_object_destroyed` comment.
