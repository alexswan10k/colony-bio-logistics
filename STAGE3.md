## Review-driven fixes (REVIEW_STAGE3.md, commit fefbc08)
### CRITICAL — autonomous engagement now lands strikes
`game.get_entity_by_unit_number` cannot see `unit`/`unit-spawner` prototypes in Factorio 2.1 (no
`get-by-unit-number` flag), so the old `patrol.engage` resolved `nil`, `should_disengage(nil)` returned true,
and no strike ever fired. Fixed by carrying `pick.entity` from `patrol.step` into `rec.target` and using it
directly in `patrol.engage` (`patrol.lua:253`); `rec.target_un` is kept only for the plain-data blacklist.
`resume_travel(..., keep_target)` preserves both across failed paths; `on_command_completed` keeps them in sync.
**`m3_patrol` now proves this end to end** (phase B1/B2): a biter is killed and an isolated biter-spawner
(350 HP) is destroyed with *zero* `militia.patrol_strike` calls from the spike — only `patrol.engage` calls it.

### MAJOR — dead patrollers no longer leak squad slots
`work.lua` nils `storage.unit_state[un]` on destruction, so every timer cleanup path that validates through
`valid(st)` returned early and left a stale `colony.patrols[un]`. The `on_object_destroyed` handler
(`patrol.lua:365-378`) now prunes the patrol lease **without requiring unit_state**, bumps `colony.patrol_seq`
to invalidate deferred timers, and clears the label. `m3_patrol` phase F kills a patroller through the real
engine path (`m.die()`), asserts `c.patrols[mun] == nil`, and proves the post re-recruits into both `POST_SQUAD`
slots.

## Deviations / reviewer scrutiny points
- **Nearest-first spawner bias (documented, not "fixed"):** `target_select` is strictly nearest-first with ties
  by unit number (shared shape with `garrison.nearest`). A live spawner emits units nearer than itself, so in a
  real fight the patrol clears the nearer biters before the nest — which is still nest-clearing progress. The
  isolated-nest spike (all biter units swept every 5 ticks) proves that when no nearer hostile exists the spawner
  itself is selected and destroyed autonomously (350 HP → 0, zero spike strikes). Changing the selection rule to
  prefer spawners would diverge from the shared garrison rule and is deliberately not done.
- **Duplicate `patrol.engage` timers can stack** when `attack_area` completes early and `patrol.step` re-engages
  before the previous engagement timer fires. Stale timers are harmless (they require `st.state ==
  "patrol-engage"` and a matching generation `seq`), but they can accelerate damage. This is why the isolated
  nest dies quickly; it is not a correctness issue, and serialising the timers would change the checksum.
- **No `s20_nest` probe**: PLAN made it conditional on patrols being silently deleted on failed paths.
  s19_defence and m3_patrol prove `allow_destroy_when_commands_fail = false` keeps the unit alive.
- **`patrol.step` scans with a 45-tick period over a 16-tile box**, not per tick; dispatch stops entirely when
  no post has waypoints.
- **Gear is kept on whistle preemption** (`abort_intents.gear` carries it into the lease, as for any militia).
- **Bytecode**: `scripts/__pycache__/artlib.cpython-313.pyc` restored with `git checkout --`; none committed.
- **Active patrols finish their cached route when their post is mined**; the next dispatch will not re-post them.
